## Cash and durable transaction contract

[ConstructionAccounting](../src/FreeTrain.Online.Simulation/ConstructionAccounting.cs)
uses raw signed Int64 money, **15,000,000,000 initial cash** and an authoritative
**10,000,000,000 bankruptcy increment** by default. Spending subtracts first;
negative cash receives the smallest number of increments needed to reach zero
or above. Exact zero receives none. There is no affordability precheck and no
authoring-mode exemption. The calculation uses a widened closed form of the
source loop, avoiding unbounded loop execution. The subtraction, resulting cash,
sequence and cumulative rescue count must fit Int64; nonpositive increments reject.

The four built-in source account genres retain their original contribution GUIDs:
RailService, RoadService, Subsidiaries and Others. P4 normally spends under
RailService; stationary-accessory demolition uses Subsidiaries. Rescue funding is
recorded separately from expenditure and is not invented genre sales: source
`transact()` adds cash without `history.earn()`.

`ConstructionAccountState` captures initial cash, economic settings and the ordered
immutable journal. Each `AccountTransaction` stores a positive stable sequence,
mixed-world revision, absolute source-game minute, operation identifier, genre,
expenditure, rescue count and resulting cash. Same-operation spend calls share
revision/time/operation; sequences preserve their order. Zero-valued spend calls
are records, whereas operations with no spend caller create no journal entry.

`Restore` validates the complete journal in one linear replay, including source
settings, genres, amounts, sequence, monotonic time/revisions, same-revision context,
rescues and cash. Cash, next sequence and cumulative rescues are derived, not
independent mutable totals. Tests JSON-round-trip this detached record and continue
booking exactly. This is the input contract for P4-05 persistence, not a new save
format. Settings cannot be changed retroactively under existing history; future
economic-setting changes need their own versioned history contract.

P8 owns earnings, debt/deposits, interest, reports and balance sheets. Source
day/month/April fiscal-year summaries can use journal timestamps and expenditure
genres alongside the authoritative session clock. This slice introduces no second
clock, history rollover scheduler, debt or process-local notification preference.
Consumers can derive bankruptcy notifications from committed rescue records.

## Operation booking

[RailwayBooking](../src/FreeTrain.Online.Simulation/RailwayBooking.cs) constructs
read-only `ConstructionBooking` quotes with ordered `AccountCharge` entries and a
checked total. Define `M(h) = -2*h` below ground, otherwise `h+1`.

| Operation | Booking contract |
| --- | --- |
| Normal build | Sum `6,000,000*M(z-ground)+reclaimedValue` over inclusive charged cells, including unchanged endpoint attachment. Reclamation comes from actual source entity values; no prototype or generic resale amount is substituted. |
| Normal remove | `2,000,000*(abs(endZ-water)+1)*eligibleRailCells`. Eligibility counts any rail without a car even if detach changes nothing. |
| Slope build/remove | Once per resolved owner: `40,000,000*M(baseZ-water)` / `8,000,000*(abs(baseZ+1-water)+1)`. Local ground does not replace water. |
| Bridge/girder | Inclusive per-cell height pricing: build `6,000,000*M(z-ground)`, remove `2,000,000*M(z-ground)`, including unchanged/skipped cells. Both retain the starting-cell underwater early-zero predicate. No reclamation surcharge is added. |
| Tunnel | Build `12,000,000` per newly created cell, including normal gap rails; remove `4,000,000` per restored tunnel cell, excluding the destination and protected cars. |
| Garage | Build `6,500,000` per inclusive cell, including replacement. Removal takes half-open axis matches, including car-blocked matches; each match adds `200,000` to the running subtotal and **every iteration spends that subtotal**, including nonmatches. |
| Stationary accessory | Completion spends declared price under RailService; removal spends `500,000*sizeX*sizeY` under Subsidiaries, independently of height. |
| Signal/pole/speed/support/site cancellation | No spend caller: use the empty booking. There is no additional automatic-pier price. |

Coordinate differences widen before subtraction, `abs`, baseZ+1 and multiplication.
Products, per-cell sums, reclamation and ordered-charge totals reject overflow.
For example the literal three dry cells cost **18,000,000**, and the reviewed
source Int32-intermediate case preserves **18,000,000,000** through Int64 widening.

These functions price **already validated tool facts**. They do not implement or
authorize route snapping, terrain legality, endpoint selection, component/car
protection, actual reclamation or demolition. Those remain P4-06 onward. In
particular a zero quote is not a legality result, and a legal source no-op can
still cost money. Future previews and commits must call the same calculator over
fresh authoritative facts rather than trusting a browser-supplied count or price.

## Atomic publication and handoff

[MixedConstructionState](../src/FreeTrain.Online.Simulation/MixedConstructionState.cs)
combines [MixedWorld](web-parity-railway-state.md) with immutable accounts.
`Replace` first constructs and validates the whole terrain/rail successor and
shared allocator, then stages every source spend call. Only after both succeed
does it return one replacement object. Publishing that object publishes all four
subsets. Failure after geometry validation or even after an earlier staged spend
leaves all original objects unchanged. No listeners run during detached work.

The mixed revision groups journal entries and fences geometry. Rebooking the
same revision rejects. No-spend operations still advance the mixed revision;
their immutable accounts can be shared unchanged. Charged no-ops and zero-cost
geometry changes both remain representable. There is no separate cash setter or
construction-mode waiver in this transaction boundary.

P4-05 must embed this publication unit in the existing session FIFO and retain
provenance, mode, clock, random streams, roles, epoch/content fences and session
revision. Save/wire input validation must restore the journal and mixed graph
before publication, require journal revisions not newer than mixed geometry, and
bound admission/history payloads deliberately. Authoritative command handlers
must revalidate operation facts and recompute booking before calling `Replace`.
Calling `MixedWorld.Replace` alone is not a booked live-command path. There is no
new dispatch/profile enablement before P4-05. P4-21/23 retain full persistence,
continuation and legal-city resource/capacity acceptance.
